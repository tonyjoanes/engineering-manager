# DevOps Engineering Career Ladder & Success Framework

A comprehensive guide to help DevOps engineers understand what they need to do to succeed and grow in their role.

## The Problem

**DevOps engineers often struggle with:**
- Unclear expectations
- "Am I doing the right things?"
- "How do I get promoted?"
- "What should I be learning?"
- "Is this my responsibility?"

**This guide provides:**
- Clear role definitions at each level
- Success criteria and competencies
- Career progression path
- Concrete examples of work
- How to support their growth

## DevOps vs Platform Engineering vs SRE

**First, clarify the role:**

### DevOps Engineer
**Focus:** CI/CD, automation, infrastructure, enabling product teams
**Work:** Build pipelines, automate deployments, infrastructure as code, tooling
**Mindset:** "Make it easy for developers to ship"

### Platform Engineer
**Focus:** Internal platforms, developer experience, self-service
**Work:** Developer portals, golden paths, platform products
**Mindset:** "Build products for internal developers"
**Note:** See [Platform Engineering guide](./platform-engineering-devex.md)

### Site Reliability Engineer (SRE)
**Focus:** Reliability, scalability, observability, production health
**Work:** SLOs/SLIs, incident response, capacity planning, reliability improvements
**Mindset:** "Keep it running reliably at scale"

**Often overlap in practice - clarify for your org.**

## The DevOps Engineer Career Ladder

### Level 1: Junior DevOps Engineer (0-2 years)

**Core Responsibilities:**
- Assist with CI/CD pipeline maintenance
- Execute infrastructure changes (with guidance)
- Monitor systems and respond to alerts
- Write basic automation scripts
- Document processes
- Learn tools and technologies

**Technical Competencies:**
- Basic Linux/system administration
- Version control (Git)
- Scripting (Bash, Python basics)
- Understanding of CI/CD concepts
- Basic networking knowledge
- Containerization basics (Docker)

**Success Looks Like:**
- Completes assigned tasks reliably
- Asks good questions
- Documents what they learn
- Improves existing automation
- Handles routine incidents with guidance
- Shows curiosity and learning

**Example Work:**
- Update deployment scripts
- Fix broken CI/CD jobs
- Add monitoring for new service
- Write runbooks for common tasks
- Automate manual processes
- On-call with senior backup

**What NOT to Expect:**
- Designing architecture
- Independent decision-making on critical systems
- Leading projects
- Production changes without review

**Career Goals:**
- Master fundamental tools
- Build solid Linux/cloud foundations
- Understand deployment pipelines end-to-end
- Develop troubleshooting skills
- Ready for Level 2 in 18-24 months

---

### Level 2: DevOps Engineer (2-4 years)

**Core Responsibilities:**
- Own CI/CD pipelines for services
- Design and implement infrastructure
- Automate operational tasks
- Participate in on-call rotation independently
- Mentor junior engineers
- Improve system reliability

**Technical Competencies:**
- Strong Linux/Windows administration
- Infrastructure as Code (Terraform, CloudFormation)
- CI/CD platforms (Jenkins, GitLab, GitHub Actions)
- Container orchestration (Kubernetes basics)
- Cloud platforms (AWS/GCP/Azure)
- Monitoring and logging (Prometheus, ELK, Datadog)
- Scripting and automation (Python, Go)
- Security basics

**Success Looks Like:**
- Independently owns pipelines and infrastructure
- Proactively identifies and fixes issues
- Reduces toil through automation
- Handles incidents effectively
- Provides good estimates
- Collaborates well with developers
- Makes systems more reliable

**Example Work:**
- Migrate service to Kubernetes
- Build new CI/CD pipeline from scratch
- Implement infrastructure as code for team
- Create automated backup/recovery system
- Set up comprehensive monitoring
- Lead incident response
- Reduce deployment time by 50%

**What NOT to Expect:**
- Cross-team platform initiatives (yet)
- Setting DevOps strategy
- Mentoring multiple people
- Architecting company-wide systems

**Career Goals:**
- Deep expertise in core tools
- Handle complex problems independently
- Influence team practices
- Ready for Senior in 2-3 years

---

### Level 3: Senior DevOps Engineer (4-7 years)

**Core Responsibilities:**
- Lead infrastructure and DevOps initiatives
- Design scalable, reliable systems
- Mentor team members
- Drive best practices adoption
- Improve team productivity significantly
- Cross-team collaboration
- Technical decision making

**Technical Competencies:**
- Expert-level infrastructure management
- Advanced Kubernetes (operators, custom resources)
- Multi-cloud architecture
- Security and compliance
- Performance optimization
- Disaster recovery planning
- Cost optimization
- Architecture design

**Success Looks Like:**
- Delivers complex projects independently
- Improves metrics significantly (DORA metrics)
- Mentors and develops others
- Reduces operational burden
- Makes good technical decisions
- Trusted advisor to product teams
- Leads incident resolution

**Example Work:**
- Design and implement multi-region infrastructure
- Build company-wide deployment platform
- Lead migration to Kubernetes
- Implement comprehensive disaster recovery
- Reduce infrastructure costs by 30%
- Create golden path for new services
- Mentor 2-3 junior/mid-level engineers
- Present at tech talks/conferences

**Expanded Impact:**
- Team-level impact (not just individual)
- Multiplier effect through mentoring
- Setting technical direction
- Influencing engineering culture

**Career Goals:**
- Become technical leader
- Deep specialization or broad expertise
- Ready for Staff/Principal or Engineering Manager

---

### Level 4: Staff DevOps Engineer (7-10+ years)

**Core Responsibilities:**
- Set technical strategy for DevOps/Platform
- Lead organization-wide initiatives
- Solve ambiguous, complex problems
- Influence engineering culture
- Technical leadership without authority
- Strategic planning
- External visibility (conference talks, blog posts)

**Technical Competencies:**
- Expert in multiple domains
- System design at scale
- Cost/performance/reliability trade-offs
- Emerging technologies evaluation
- Security architecture
- Business acumen
- Strategic thinking

**Success Looks Like:**
- Organization-level impact
- Shipping multi-quarter initiatives
- Changing how org works
- Thought leadership
- Critical technical decisions
- Mentoring senior engineers
- Measurable business impact

**Example Work:**
- Design platform strategy for next 2 years
- Lead company cloud migration
- Build new platform serving 100+ teams
- Establish DevOps culture/practices
- Reduce MTTR organization-wide
- Define SLO framework for company
- Technical advisor to executives
- Industry thought leader

**Impact:**
- Multiple teams/org-wide
- Long-term strategic
- Multiplies effectiveness of many engineers
- Shapes company technical direction

**Career Path:**
- Principal Engineer (deeper technical)
- Engineering Manager (people leadership)
- Director of Platform/DevOps
- CTO track

---

### Level 5: Principal/Distinguished DevOps Engineer (10+ years)

**Core Responsibilities:**
- Company-wide technical strategy
- Solve critical business problems with technology
- Industry thought leadership
- Mentor Staff+ engineers
- Strategic technical initiatives
- Executive partnership
- External representation

**Technical Competencies:**
- Deep expertise + broad knowledge
- Business and technology alignment
- Industry trends and innovation
- Large-scale system design
- Cross-functional leadership
- Communication and influence

**Success Looks Like:**
- Company-defining impact
- Industry recognition
- Strategic business outcomes
- Lasting technical improvements
- Develops senior leaders
- Trusted by C-suite

**Example Work:**
- Define 5-year technical infrastructure strategy
- Lead acquisition integration
- Build platform used industry-wide
- Establish engineering practices adopted broadly
- Prevent company-threatening technical risk
- Advisory to CEO/CTO on technology strategy

**This is rare and exceptional.**

## Success Metrics by Level

### Junior DevOps Engineer Metrics

**Measure:**
- Tasks completed on time
- Quality of work (rework needed?)
- Questions asked (learning?)
- Documentation contributions
- Incident response time (with guidance)

**Goals:**
- 90% of assigned tasks completed on time
- Less than 20% rework rate
- Active participation in learning
- Contribute to runbooks monthly

### Mid-Level DevOps Engineer Metrics

**Measure:**
- Pipeline reliability (uptime %)
- Deployment frequency improvement
- Automation coverage increase
- Incident MTTR
- Team satisfaction with tools

**Goals:**
- 99%+ CI/CD uptime
- Increase deployment frequency 2x
- Automate 50% of toil
- MTTR under 2 hours for their services
- Positive feedback from developers

### Senior DevOps Engineer Metrics

**Measure:**
- Team DORA metrics improvement
- Infrastructure cost reduction
- Developer satisfaction score
- Mentees' growth
- Cross-team initiative success

**Goals:**
- Improve team deployment frequency 3x
- Reduce infrastructure cost 20%
- Developer satisfaction >4/5
- 2 mentees progressing well
- Complete 1-2 major initiatives per quarter

### Staff+ DevOps Engineer Metrics

**Measure:**
- Organization DORA metrics
- Platform adoption rate
- Incident reduction org-wide
- Strategic initiative completion
- Industry impact (talks, posts, etc.)

**Goals:**
- Move org to "High" or "Elite" DORA
- 80%+ platform adoption
- 50% reduction in critical incidents
- Complete multi-quarter strategic initiatives
- External thought leadership

## Common Role Clarity Issues

### "I Don't Know What I Should Be Working On"

**Root Cause:** Unclear priorities or responsibilities

**Solution:**
- Weekly 1:1s with clear priorities
- Quarterly goal setting (OKRs or similar)
- Written role expectations
- Regular feedback on alignment

**Manager Action:**
Create priority list:
```
This Quarter Priorities:
1. [High priority project/area]
2. [Medium priority]
3. [Learning goal]

Weekly Focus:
- 60% on priority #1
- 30% on priority #2
- 10% on learning/improvement
```

### "Am I Doing Senior-Level Work?"

**Root Cause:** Unclear level expectations

**Solution:**
- Share this career ladder
- Regular self-assessment against level
- Specific examples of level-appropriate work
- Gap analysis and development plan

**Manager Action:**
Quarterly review:
```
Current Level: L2
Working Towards: L3

Demonstrating L3:
✓ Led Kubernetes migration (complexity)
✓ Mentoring Junior DevOps (mentorship)

Gap to L3:
✗ Cross-team impact (still single team)
✗ Architectural decisions (guidance needed)

Development Plan:
- Q3: Lead cross-team logging standardization
- Q4: Shadow Staff engineer on architecture reviews
```

### "What Should I Learn Next?"

**Root Cause:** No clear skill development path

**Solution:**
- Skills matrix assessment
- Learning plan tied to career goals
- 70-20-10 development model

**Manager Action:**
Create learning plan:
```
Current: L2 DevOps Engineer
Target: L3 in 18 months

Skill Gaps:
1. Kubernetes depth (currently 2/5, need 4/5)
2. Architecture design (currently 2/5, need 3/5)
3. Mentoring (currently 1/5, need 3/5)

Learning Plan:
Q3:
- 70%: Lead k8s migration project (on the job)
- 20%: Pair with Senior on architecture (relationships)
- 10%: CKA certification course (formal learning)

Q4:
- 70%: Own architecture for new service
- 20%: Mentor new Junior DevOps
- 10%: Advanced k8s course
```

**Create for each engineer:**

```markdown

2. [Secondary responsibility]
3. [Tertiary responsibility]

## This Quarter's Priorities
1. [Project/initiative] - [Success metric]
2. [Improvement area] - [Success metric]
3. [Learning goal] - [Success metric]

## How Success is Measured
- [Metric 1]: [Target]
- [Metric 2]: [Target]
- [Qualitative measure]: [What good looks like]

## Growth Areas for Next Level
1. [Skill/competency gap]
2. [Impact expansion needed]
3. [Leadership opportunity]

- Weekly 1:1s
- [Training/resources]
- [Mentorship opportunities]
- [Projects that develop skills]

## Questions or Concerns
[Space for their input]
```

**Review quarterly, update as needed.**

### The 30-60-90 Day Plan (for new DevOps hires)

**First 30 Days: Learn**
- Setup development environment
- Shadow team members
- Read all documentation
- Understand current systems
- Fix first small bug/improvement
- Join on-call shadow rotation

**Days 31-60: Contribute**
- Own first real project (guided)
- Participate in incidents
- Start improving documentation
- Propose first automation
- Build relationships with dev teams

**Days 61-90: Own**
- Lead a small project independently
- On-call primary (with backup)
- Deliver measurable improvement
- Identify next improvements
- Fully productive team member

## Supporting Growth

### Career Development Conversations

**Quarterly career 1:1 (separate from regular 1:1):**

**Agenda:**
1. How do you feel about your growth? (10 min)
2. Where do you want to be in 1-2 years? (10 min)
3. What gaps exist to get there? (15 min)
4. What projects/experiences would help? (15 min)
5. Action plan and next steps (10 min)

**Use career ladder as guide:**
- "You're here at L2"
- "To get to L3, you need X, Y, Z"
- "Here are opportunities to develop those"

### Projects for Growth

**Junior → Mid:**
- Own full CI/CD pipeline for service
- Lead small infrastructure migration
- Automate manual process end-to-end
- Document complex system

**Mid → Senior:**
- Lead cross-team initiative
- Mentor junior engineer
- Design architecture for new service
- Present at tech talk

**Senior → Staff:**
- Lead multi-quarter strategic project
- Define standards/practices for org
- Mentor senior engineers
- External thought leadership

**Match projects to development needs.**

## Red Flags and Course Correction

### Warning Signs

**Engineer doesn't understand expectations:**
- Working on wrong things
- Constantly asking "Should I?"
- Frustrated or disengaged
- Surprise in performance reviews

**Action:** Clarify expectations document, more frequent check-ins

**Engineer stuck at level:**
- Same level 3+ years
- Not developing new skills
- Doing same work repeatedly
- No clear growth path

**Action:** Career development conversation, stretch projects, gap analysis

**Engineer overwhelmed:**
- Missing deadlines
- Quality dropping
- Burnout signs
- Too much scope

**Action:** Reduce scope, provide support, reassess level expectations

**Engineer bored:**
- Checked out
- Minimal effort
- Looking elsewhere
- Under-challenged

**Action:** Bigger challenges, lead projects, growth opportunities

## Making It Work

### Implementation Steps

**Week 1:**
1. Share this career ladder with team
2. Discuss in team meeting
3. Get feedback and adjust for your context

**Week 2-4:**
1. Create expectations document for each engineer
2. 1:1 to discuss and align
3. Self-assessment exercise

**Month 2:**
1. Quarterly career development 1:1s
2. Create development plans
3. Identify growth projects

**Ongoing:**
1. Monthly progress reviews in 1:1s
2. Quarterly self and manager assessments
3. Annual career conversations
4. Continuous feedback

### Key Principles

**Clarity:**
- Written expectations
- Regular discussion
- Examples provided
- No surprises

**Growth:**
- Always developing
- Clear path forward
- Support provided
- Celebrate progress

**Fairness:**
- Same ladder for all
- Objective criteria
- Consistent application
- Merit-based advancement

**Flexibility:**
- Adapt to your org
- Individual development paths
- Different strengths valued
- Multiple ways to contribute
